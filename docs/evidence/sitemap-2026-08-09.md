# Sitemap covers the five human-facing pages — live-deployment verification

Date: 2026-08-09
Scope: the five public tinystudio.io pages — `index.html` (home) and `audit.html`, `agents.html`, `pricing.html`, `specimen.html` (harvested round-5 candidate, scout 2026-08-09).
This receipt records a live measurement of the deployed site. It is behavior evidence, not a source check, and it does not claim anything about ranking, traffic, or search results.

## What was measured

The leak audit this site sells flags sites whose sitemap does not cover their
human-facing pages: a crawler discovers pages through links and the sitemap,
and every page missing from the sitemap is left to be found by chance (or not
at all) even when `robots.txt` allows it. The round-5 harvest found exactly
that fault on this site's own sitemap: before the fix, `public/sitemap.xml`
listed only the root, `/offer.md` and `/llms.txt` (verified against the parent
of the fix commit cd9184c) — so the four sibling human-facing pages
(`/audit`, `/agents`, `/pricing`, `/specimen`) were invisible to crawlers
even though `robots.txt` allows every path.

The fix (PR #36, "seo: publish complete sitemap covering the five human-facing
pages", merged 2026-08-09) made the sitemap cover the complete indexable
surface: all five human-facing pages at their clean extensionless URLs (the
addresses the worker serves; the `.html` forms 307-redirect to them) plus the
two machine-readable mirrors (`/offer.md`, `/llms.txt`) that were already
listed. It also added a dedicated regression suite (`scripts/test-sitemap.mjs`,
wired into `npm test` as `test:sitemap`) that fails the build if any part of
the guarantee drifts: the exact ordered loc set changes (adding, dropping or
reordering a loc), a loc is not an absolute `https://tinystudio.io/` URL, an
HTML page uses its `.html` form instead of the clean twin, a trailing slash
appears anywhere but on the root, a stale path reappears (`/brief-requested`
is noindex by design, `/agent-desk` is legacy), the urlset schema drifts from
byte-shape-identical (standard XML declaration, sitemaps 0.9 namespace, `url`
blocks carrying only `<loc>`), or `robots.txt` stops pointing at the sitemap.
The suite also runs against embedded "known bad shape" fixtures so it proves
it rejects every regression it guards.

This receipt closes the remaining gap: the live deployment was never measured.
The measurement below verifies the deployed sitemap as served to a crawler.

## Environment

- Live target: `https://tinystudio.io/sitemap.xml`, served by the deployed
  Cloudflare Worker (ASSETS binding, which serves the static files verbatim;
  see `src/worker.js`).
- The served sitemap was fetched over HTTPS and byte-compared against
  `public/sitemap.xml` on origin/main; every `<loc>` was then probed over
  HTTPS and checked for a 200 response; `robots.txt` was checked for the
  `Sitemap:` directive; the noindex page was confirmed excluded by reading
  its served `<meta name="robots">` tag.

## Results (deployed site, 2026-08-09)

### The served sitemap

`https://tinystudio.io/sitemap.xml` returns 200 and is **byte-identical** to
`public/sitemap.xml` on origin/main (clean `diff`). It carries exactly seven
`<url>` blocks, each with a single `<loc>` and nothing else:

| # | loc | probed HTTP |
|---|---|---|
| 1 | `https://tinystudio.io/` | 200 |
| 2 | `https://tinystudio.io/audit` | 200 |
| 3 | `https://tinystudio.io/agents` | 200 |
| 4 | `https://tinystudio.io/pricing` | 200 |
| 5 | `https://tinystudio.io/specimen` | 200 |
| 6 | `https://tinystudio.io/offer.md` | 200 |
| 7 | `https://tinystudio.io/llms.txt` | 200 |

All five human-facing pages are present at their clean extensionless URLs —
the four pages missing before the fix (`/audit`, `/agents`, `/pricing`,
`/specimen`) are now listed — and every loc serves HTTP 200.

### Exclusions held

- `robots.txt` (live at `https://tinystudio.io/robots.txt`) keeps
  `Sitemap: https://tinystudio.io/sitemap.xml`.
- `/brief-requested` (noindex signup redirect) serves
  `<meta name="robots" content="noindex, nofollow">` and is correctly absent
  from the sitemap; legacy `/agent-desk` is absent too — both locked out by
  the regression suite.

## Limitation

This is a live-deployment measurement, not a CI gate: the checks above run
manually, so a future deployment could still regress while CI stays green.
What prevents that regression today is the source guard in
`scripts/test-sitemap.mjs` (merged with the fix in PR #36), which fails
`npm test` on any loc added, dropped or reordered, any non-absolute URL, any
`.html` form, any extra trailing slash, any stale path, any schema drift, or
a missing robots directive. The served pages are the static files verbatim
through the Worker's ASSETS binding (`src/worker.js`), so the source guard
and the served bytes cannot drift unless the Worker's asset serving itself
changes.
